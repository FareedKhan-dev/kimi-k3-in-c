KIMI K3 VERIFICATION REPORT
Verification date: 2026-11-18

Scope
-----
Build and test the C engine without model weights, then run the previously
skipped tokenizer and chat checks using the official released tokenizer files.
These checks do not establish correctness or performance on the full 2.78T
checkpoint. The full-model oracle uses the repository's small 13-layer fixture.

GNU Make: 4.4.1
GCC: 15.2.0
Built CLI: k3 2.0.0 (Linux executable; run through WSL)
Python reference library: tiktoken==0.13.0 in an isolated WSL virtual environment

Build tool selection and filesystem workaround
---------------------------------------------
The original PowerShell command, make test, failed because Make was not on the
Windows PATH. Ubuntu WSL already supplied GNU Make, GCC, and Python, so no native
Windows compiler or Make installation was required.

An initial WSL test run compiled successfully but failed the state-file
publication permissions assertion on the Windows-mounted filesystem:
  observed mode 0777; expected 0644 with umask 0022.

Placing BUILD on WSL's Linux filesystem resolved that failure.
From the repository root in PowerShell:

  wsl -d Ubuntu -- make -j2 test BUILD=/tmp/kimi-k3-build

This keeps objects and generated test fixtures in Linux storage. Executables
remain under the repository's bin/ directory.

Tokenizer verification commands
-------------------------------
The following Bash commands were executed through Ubuntu WSL, from the
repository root. Use wsl -d Ubuntu from PowerShell to enter that environment.

  export K3_TOK_FILES=/root/.cache/kimi-k3-tokenizer/f831ab66814297da540d832a5235f8e904f29d06

  ./bin/test_tok "$K3_TOK_FILES" roundtrip README.md
  ./bin/test_chat "$K3_TOK_FILES"

The reference comparison reads the official split pattern from
tokenization_kimi.py using AST parsing and compares the C tokenizer with
tiktoken using the same released vocabulary.
